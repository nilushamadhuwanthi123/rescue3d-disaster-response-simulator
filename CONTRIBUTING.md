# Contributing to Rescue3D

## Branches

- `main` is protected: no direct pushes, no force-pushes, PRs required.
- Work on a `feature/<owner>-<scope>` branch, one meaningful unit of work per branch.
- Keep branches in sync with `main` before opening a PR.

## Commits

Use Conventional Commits (`feat:`, `fix:`, `chore:`, `test:`, `docs:`, `refactor:`).
Keep commits scoped and logical — no empty or filler commits.

## Before opening a PR

```bash
npm run lint
npm run typecheck
npm run test
npm run build
```

## Pull requests

- Fill in the PR template.
- Link related issues.
- Include test results.
- Request review before merging.
